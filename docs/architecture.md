# 架构与运行契约

## 三种 Git 边界

工作区管研究意图、证据、任务和稳定约束；代码仓库管实现、环境依赖和测试；未来论文仓库管 LaTeX 与投稿版本。`workspace.local.json` 保存本机 code_repo/paper_repo，不提交绝对路径。独立仓库可以在忽略的 `repos/`、`paper/` 下或外层相邻目录。不能把外层工作区自身登记为代码仓库。

参考代码是只读调查材料，放 `refrepo/` 或 `ref/<slug>/repo/`；从已有 repo.txt/来源记录重建，不纳入工作区 Git。注册命令不自动 clone。多个机器各自维护 registry，引用实验代码用 Git commit，不用机器绝对路径代替版本。

## 一件事只有一个权威状态

人类意图在 research/brief.md；约束在 spec/；任务状态/事件在 task meta.json；科学证据在 research；原始执行输出在 .runtime。任务完成仅表示交付验收，假设可能被否定。报告从证据生成，不能倒过来用“漂亮报告已写完”证明实验已做完。

工作区脚本对 JSON 使用临时文件 + fsync + replace。任务 CLI、文献目录、实验执行和编排器分别采用本地 flock 防止同类并发写。原始结果不覆盖，多个 Agent 由主 Agent 整合。归档操作先更新 metadata 后 rename；极端崩溃可能在 active 中留下已关闭状态，需人工核对并完成移动，不丢弃记录。

## 可移植技能

每个执行技能的 scripts/ 自带 runtime.py；这一个小型标准库运行时有意在五个 skill 中保持相同内容，避免复制单一 skill 后还依赖兄弟目录。测试断言副本哈希一致。修改时同步副本，不能只补一个。共享研究协议在简短 AGENTS/spec 中，而非每一步再加载庞大的通用写作家族。

这种“运行依赖自包含”不代表单个 SKILL.md 能凭空完成整条科研链：autopilot 会明确调用已经安装的其他专业技能，ideation/writing 是认知流程和模板，不为了看起来可自动化而增加无用脚本。

## 双层自动推进

交互式：Codex 主 Agent 按技能进行下一步，原生 subagents 做独立检索/探索/复核，任务与证据落盘。无需后台 hook。

脚本式：loop.py 在你本机前台驱动 codex exec。一轮 executor 用 workspace-write，一轮 reviewer 用新的 read-only 会话。结构化响应经过 schema 和本地字段检查；必须存在研究产物，核对哈希、原始约束和先前进展。复核 proceed 只表示允许工作流继续。主模型和 reviewer 使用同一个可配置模型时不是跨模型独立验证。

每轮开始前持久化时间预留，正常结束按实际耗时结算；中断后的恢复保留未结算预留，不能通过反复 resume 重置预算。新一轮使用新输出路径，不接受遗留响应。STOP、超时、错误、复核阻塞、连续无进展、修订上限或总预算耗尽都会保存状态后退出；没有默认无限重试或跨机器调度。

## 实验可信度

实验脚本只执行指定 argv，不拼 shell；需要匹配登记仓库 HEAD。源代码 fingerprint 包含 HEAD、diff hash、未跟踪文件 hash；脏状态执行显式标记，confirmatory 拒绝脏代码。此记录不包含完整依赖环境/所有未跟踪文件字节，不声称仅凭收据可完全复现。真实复现还需独立代码仓库环境锁、数据版本、机器信息和原始输出。

每个 seed 输出到全新目录，以退出码、指标数值与源代码漂移决定状态。配对分析只接受成功的非 smoke 结果、相同数据/指标/对照组以及相同 seeds；CI 是配对 seed bootstrap 描述性区间，不是显著性检验或数据采样置信度。审计器能查结构、hash、有限数、seed 覆盖和已有原始指标一致性，不能机械证明新颖性、因果有效性或引用语义。

## 安全与隐私边界

子进程在用户账户权限内运行。超时、进程组、环境 allowlist 和日志大小限制是防误操作措施，不是恶意代码隔离；已有代码能自行打开文件、访问网络或逃逸进程组。对不可信实验另配容器/OS 沙箱，不要把本模板当安全产品。Codex 仍受自己的审批和沙箱控制，项目网络默认不开放；用户手工从终端执行的 Python 程序遵循主机权限。

已知密钥字符串脱敏不识别全部私密信息。任务正文、代码 diff、搜索词也可能敏感；参考私有旧仓库时只迁移通用方法，不把既有科研内容发布到公共模板。脚本不上传结果、发 PR 或 push；这些操作须单独授权。
