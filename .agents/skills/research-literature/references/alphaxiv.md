# alphaXiv（论文检索与阅读服务）

The user's `ResearchTemplate/scripts/paper_retrieval/alphaxiv.py` is the migration reference. The service is alphaXiv, not “alphakiv”. Prefer an already available native alphaXiv connector when it provides the needed operation. The bundled Python script provides a standalone, read-only alternative without installing an MCP server or another workspace.

Endpoint: `https://api.alphaxiv.org/mcp/v1`. Authentication: `ALPHAXIV_API_TOKEN`, with `ALPHAXIV_API_KEY` as an alias. Resolve by configuration layer first: process environment, current skill `.env`, project `.env`; an explicit empty value disables fallback. Never pass a key on the command line. Grant shell networking through the host's normal approval mechanism when needed.

```bash
python3 .agents/skills/research-literature/scripts/alphaxiv.py tools
python3 .agents/skills/research-literature/scripts/alphaxiv.py discover \
  --keywords 'robot scene synthesis' 'functional layout' --question 'Find the closest methods and evaluations' \
  --published-after 2026-01-01
python3 .agents/skills/research-literature/scripts/alphaxiv.py content https://arxiv.org/abs/2601.01234 --full-text
python3 .agents/skills/research-literature/scripts/alphaxiv.py call answer_pdf_queries \
  --args '{"paper":"2601.01234","queries":["What is the evaluation protocol?"]}'
python3 .agents/skills/research-literature/scripts/alphaxiv.py call read_files_from_github_repository \
  --args '{"githubUrl":"https://github.com/owner/repository","path":"/"}'
```

Use real identifiers; examples do not claim these papers exist. The client negotiates MCP initialization, sends the initialized notification, propagates session/protocol headers, discovers current tool schemas, checks required keys, and handles finite JSON/SSE responses. It allows only discover_papers, get_paper_content, answer_pdf_queries, and read_files_from_github_repository. Account writes are intentionally unsupported, including arbitrary calls disguised as discovery.

Remote schemas can change. `tools` is the current contract; do not invent missing parameters or treat a tool error as an empty result. Schema checking here covers required fields, not complete JSON-Schema semantics. Responses are size/time bounded; persistent subscriptions/reconnection are not implemented. Errors return nonzero without echoing raw provider error bodies or tokens.

Store returned JSON with provider/date/query context and source identifiers. Mark reports generated by the service as secondary summaries. Source text still needs passage-level verification before supporting a claim. `--full-text` is a request, not proof that the provider returned the complete original paper. Requests may disclose query text or paper identifiers to the service; do not send private research material without permission.
