# 基准与模块适配

适用：把拆出的部件变成可解释、可测试、可写的方法。课程 2.4、2.5、2.7 提供主线；接口检查、可证伪假设和公平控制为工程化补充。

## 基准不是“挑一个容易超过的数字”

先按任务匹配、数据许可、代码/权重可获得性、文档、计算资源和复现实用性选候选。优先试运行有清楚协议的实现，不把 star 数、名校、年份或期刊层级当质量证明。近期代表工作和最接近方案必须核对，但不设置“只能近两年”的机械门槛。

记录三个不同角色：开发用底座、验证改动的对照、领域代表比较方法。它们可重合，但不能只有一个刻意选弱的对照。即使自己的模型未全面领先，也可以研究成本、稳健性、边界或否定某个假设；准确写出结果，不承诺发表。

复现时锁定论文版本、仓库 commit、环境、数据版本/划分、预处理、权重、训练/推理设置、评估脚本、种子和资源。跑通只是功能检查，不能代替论文级复现。偏差大时先排查协议、单位、评估、检查点和依赖；原文与复现数值并列分组标注。不采取“跑得低就用复现、跑得高就用原文”的不对称选择。

## 模块池有三种来源

通用组件、同领域论文的部件、相邻领域可迁移的机制。每个候选只需一张卡：

- **来源与归属**：论文和实现定位，许可，原功能，是否有公开实现。
- **适配理由**：当前观察到的瓶颈、可作用的位置、为什么此任务满足原机制假设。
- **改动清单**：保留什么、改什么、为什么必须改；区分忠实复现、受启发重实现和新变体。
- **可证伪预期**：若有效，应在哪类样本、哪项指标或哪个代价维度出现什么变化；什么结果会推翻它。
- **最小验证与预算**：基准、单模块、组合、替代解释控制；资源限制和停止条件。

先试信息量高、成本可承受的少量候选，而非默认穷举几十个模块。没有代码也能按描述重实现，但必须记录未披露细节及假设，不能称逐位复现。

## “缝”的具体接口检查

从数据源到输出画一条链，标明部件所在位置，再逐项检查：

| 检查 | 必须回答 |
|---|---|
| 语义 | 输入是 token、帧、对象、点、关系还是全局向量？对应性是否保留？ |
| 形状 | 维度、布局、长度、掩码、batch 广播、dtype/device 是否匹配？ |
| 训练 | 梯度是否连通，新增参数如何初始化，损失尺度与采样如何变化？ |
| 推理 | 是否使用未来帧、标签、测试集统计或训练期才有的信息？ |
| 代价 | 参数、显存、训练/推理时间、额外数据/调用量如何变化？ |
| 公平性 | 对照是否获得相同输入、搜索预算和选择机会？ |

先做最小形状/梯度/数据泄漏检查，再做有意义的实验。测试通过只能说接口能运行，不能说模块有效。加一个 adapter、改符号、重命名，不自动成为新贡献；方法正文如实描述继承和真实变化。

## 用实验决定是否保留，而非用故事救结果

在预算内测 A、A+b、A+c、A+b+c；若部件相互依赖，说明哪些组合无定义，并构造语义有效的替代对照。结果无效时，记录失败、检查实现、收缩假设或移除组件，不把失败的模块强写成“不可或缺”。预算耗尽就交付已有结论与缺口，不启动无止境搜索。

交接写作的最小包：最终结构及代码定位、继承/新增表、训练推理差异、实验收据、成本、未支持的机制解释。具体结果组织见 [实验与证据](experiments-and-evidence.md)。
